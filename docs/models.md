# 🧠 LLM モデル構成と推奨スペック (Model Architecture & Hardware)

本 Bot は、単一の巨大モデルにすべての負荷を集中させるのではなく、役割ごとに特化した **3〜4 種類のモデルを連携運用** するマルチモデル・アーキテクチャを採用しています。

---

## 1. 用意すべきモデルの規模と個数（マルチモデル運用）

| 役割 | 推奨モデル例 | 推奨パラメータ規模 | 役割と動作タイミング |
| :--- | :--- | :---: | :--- |
| **① メイン会話モデル**<br>(Main Persona) | `Qwen3.5-9B`<br>`Qwen2.5-14B/32B`<br>`Qwen3.6-35B-A3B` | **8B〜35B**<br>(Q4_K_M 等) | Discord ユーザーとのメイン対話、ペルソナ口調の再現、ゲーム進行。思考モード（`<think>`）対応。常に VRAM 常駐（`keep_alive=-1`）推奨。 |
| **② 中間分類モデル**<br>(Middle-LLM) | `middle-llm`<br>(`Qwen3.5-9B`<br>`Qwen2.5-7B/3B`) | **3B〜9B**<br>(Q4〜Q5) | 事前意図判定（Tool Routing Gate: 外部ツール/MCP要否）、記憶選別、感情分析（Scoring）、習慣抽出、構造化JSON抽出。高速・決定論的（`temp: 0`）。120秒間 VRAM キャッシュ（`keep_alive=120`）。 |
| **③ 埋め込みモデル**<br>(Embedding) | `bge-m3` | **約 560M**<br>(1024次元) | 長期記憶（MemoryStore）のベクトル類似度検索（RAG）。FTS5 全文検索とハイブリッド結合して記憶を高速想起。 |
| **④ 画像認識モデル**<br>(Vision / 前処理) | `qwen3-vl:8b`<br>`Qwen3-VL-8B`<br>`qwen2.5-vl` | **7B〜8B** | Discord画像添付・ふたばスレ画・Webスクショの客観的キャプション＆文字起こし（OCR）。2段階パイプラインによりオンデマンドでロードし、解析完了後即座に解放（`keep_alive=0`）。 |

> [!TIP]
> **中間モデルの使い分け**:
> 返信前分析などの中間タスクは、原則として中間モデル（`middle-llm`）に寄せる設計です。ただし分類モデル用の設定（`OLLAMA_CLASSIFIER_MODEL`）は今も独立に残っており、ファクトチェック等はこちらを参照します（未設定の場合はユーティリティモデル→メインモデルの順にフォールバックします）。両方に同じモデル名を指定すれば、実質的に1モデルのスワップ運用に寄せられます。

---

## 2. ハードウェア・GPU (VRAM) の目安
ローカル GPU で運用する場合の推奨スペックです。

- **16 GB VRAM (RTX 4080 / 4070 Ti Super / RTX 3080 16GB / T4 / V100 等)**:
  - メインモデル: 8B〜14B (Q4_K_M) または 35B (軽量MoE/A3B)
  - 中間モデル: 9B (Q4〜Q5)
  - 埋め込み: BGE-M3
  - 戦略: メイン常駐 ＋ 中間モデル（120秒キャッシュ）の動的スワップ運用により、単一 GPU でも快適に稼働。
- **24 GB+ VRAM (RTX 3090 / 4090 / A5000 / A10G 等)**:
  - メインモデル: 14B〜32B (Q4_K_M / Q8)
  - 中間モデル: 9B (常時常駐可能)
  - 複数モデルを VRAM に常時展開でき、ロード待ちゼロの超低レイテンシ運用が可能。
