# 🎮 Tier Game サブプロジェクト開発ガイドライン (AGENTS.md)

本ディレクトリ（`tier_game/`）は、**Discord上で行われるティア表パーティゲーム（お題生成、選択肢提示、プレイヤー予想、スコアリング、相性度診断、ティア表画像描画）**を担当するサブプロジェクトです。

---

## 🎯 担当範囲と責務
1. **データモデルとバリデーション (`models.py`)**:
   - `TopicData`, `PlayerState`, `PlayerSubmission`, `RoundResult`, `CompatibilityPair` 等のゲームデータ構造。
   - お題と選択肢の厳格な品質検証（`TopicData.is_valid`）：簡体字・中国語の排除、自然な日本語文構造チェック、客観クイズ排除（`_OBJECTIVE_FACT_TOPIC_RE` の文脈付き判定による「の種類で〜」等主観的好み表現の誤検知防止）、AIメタ表現排除、数字・プレースホルダー排除、同語反復・自己包含排除、選択肢の表記揺れ重複正規化（`_normalize_option_key`）、性的・センシティブ表現排除（カタカナ卑語を含む BAN-86）、架空タイトル捏造・ポエティック文章排除（`_has_fictional_or_poetic_style`）、および選択肢間の概念混在・構造不揃い排除（`_has_heterogeneous_options`）。
2. **お題生成とプール管理 (`topics.py`)**:
   - AIによるリアルタイムお題生成（`generate_topic_with_ai`）と多様なプリセット（`PRESET_TOPICS`）への安全なフォールバック。
   - 生成失敗（バリデーション失敗）と最近出題キャッシュ重複（`_RECENT_TOPIC_CACHE`）を明確に分離した詳細ログ出力。
   - MemoryStore（SQLite DB）からの着想テーマ抽出（`fetch_random_db_contexts`, `_extract_clean_db_theme`）：対話分析・行動傾向メモ・内省文、カタカナ卑語、および述語・文節断片（「〜している」「〜いない」「〜存在する」「〜という呼び方」等）の完全除外、ジャンルハードコードの撤廃。
   - バックグラウンドでのお題事前生成・ストックプール（`TopicPool`）：サイズ適正化（`target_size=3`）、試行回数上限（最大6回）による過剰ループ抑止（BAN-118）、既存プール内のカテゴリ・お題除外引数（`excluded_categories`, `excluded_topics`）による重複防止、同一カテゴリや正規化後主題キーワードの重複排除（`_is_duplicate_in_pool`）。
   - 問題文末尾の冗長なルール説明（「5つ選んでS〜Dにランク付けするとしたら？」等）のサニタイズ・トリム。
   - 着想ジャンル集（`INSPIRATION_THEMES`）の10ジャンル拡充。
3. **ゲーム進行・セッション管理 (`session.py`)**:
   - ゲームフェーズ遷移（LOBBY ➜ CREATING_ANSWERS ➜ ROUND_GUESS ➜ ROUND_RESULT ➜ GAME_OVER）。
   - ホスト・回答者のティア表提出受付、タイムアウト制御、DM通知。
4. **Discord UI / インタラクション (`views.py`, `cog.py`)**:
   - スラッシュコマンド（`/tier_game` 等）の登録と制御。
   - Bot起動時のお題プリフェッチのデフォルト無効化（`TIER_GAME_PREFETCH_ON_STARTUP=False`）によるバックグラウンド推論圧迫防止。
   - Discord Select / Button 等のUIコンポーネントによる直感的なティア入力（S/A/B/C/D）。
5. **スコアリングと相性度診断 (`scoring.py`)**:
   - ティア差分計算、完全一致ボーナス、ホストボーナス算出。
   - プレイヤー間の好みの相性度診断（`evaluate_compatibility`）。
6. **ティア表画像描画 (`renderer.py`)**:
   - Pillowを用いた美麗なティア表リザルト画像の生成、およびテキスト/Embedレンダリング。

## 🚫 境界条件と禁止事項（最重要）
1. **【スコープ外ファイル編集の厳禁】**:
   - **自身が担当する `tier_game/` 配下のファイルのみを編集すること。**
   - 他モジュール（`harness/`, `ollama_bot/`, `tests/` 等）のファイルを直接変更してはならない。
   - インターフェースや外部型の変更が必要な場合は、自己判断で書き換えず、ルートエージェント（トリアージ・アーキテクト）へエスカレーションすること。
2. **DBテーマ抽出における対話分析・人物行動傾向メモの混入禁止**:
   - `memories` テーブルからの記憶抽出時、`memory_type NOT IN ('communication_style', 'behavioral_principle', 'persona_reflection', 'self_belief', 'agent_belief', 'relationship')` により対話傾向・内省・関係性メモを確実に除外すること。
   - `_extract_clean_db_theme` において、「ユーザー」「傾向」「称賛」「言葉で感謝」「追加パート」等のメタ文脈や、`^.+?(?:は|が).+?(?:傾向|使う|示す|好む|関心|言及)` 等の人物行動傾向文をテーマとして抽出せず、必ず `None` として棄却すること。
3. **選択肢の表記揺れ重複の排除**:
   - `TopicData.is_valid` において、単純な完全一致だけでなく、カタカナ→ひらがな変換および代表的な同義表記（`海苔`↔`のり`, `鰹`↔`かつお`, `鮭`↔`さけ/しゃけ`, `梅干し`↔`うめ`, `明太子`↔`めんたいこ`, `昆布`↔`こんぶ` 等）を正規化する `_normalize_option_key` を通じたキー集合で検証し、5件未満となる表記揺れ重複を絶対に通過させないこと。
4. **特定作品テーマにおける別作品キャラ混入・創作キャラの厳禁**:
   - 東方Project等の特定作品・シリーズをお題とする場合、他作品（ポケモン等）のキャラクター混入や勝手なキャラ名創作・改変を防止するため、プロンプト指示およびバリデーションを徹底すること。
5. **問題文末尾のメタ指示文（ルール説明）残存の禁止**:
   - AIが問題文末尾に「5つ選んでS〜Dにランク付けするとしたら？」等の冗長なルール説明を付与する現象を抑止するため、プロンプトでの禁止明記に加え、正規表現トリムによる二重防御サニタイズを常に行うこと。
6. **プール内お題のカテゴリ・主題重複の排除**:
   - `TopicPool._fill_worker` において、完全一致のみならず、同一カテゴリ（`'その他'` / `'一般'` を除く）または正規化後の主題キーワードがプール内に既に存在する場合はプールに追加せず再生成させ、ゲーム内の問題バリエーションを確保すること。
7. **DBテーマ抽出時のハードコード（特定ジャンル補足等）の全面禁止**:
   - `_extract_clean_db_theme` において、`f"{topic_candidate}（推理・ミステリー作品）"` などの特定ジャンル名・カテゴリ名を無条件に決め打ちで付加・ハードコードすることを厳禁とする。抽出されたキーワードそのもの、または作品名単体を正確に返却すること。
8. **センシティブ・性的・過激な怨嗟ワードの完全排除（BAN-86）**:
   - DBテーマ抽出時（`_extract_clean_db_theme`）およびお題・選択肢・カテゴリのバリデーション（`TopicData.is_valid`）において、下ネタ・性的ワード（「エロ」「セックス」「おちっこ」「ちんこ」等）や過激な嫉妬・怨嗟・攻撃的ワード（「嫉妬で狂」「狂いそう」「死ね」「殺す」等）を含むテキストを即座に `None` または `False` として棄却すること。
9. **架空タイトル捏造・ポエティック文章および概念混在の排除**:
   - 選択肢に「『』」「「」」で囲まれたポエティックな文や架空タイトルと思われる文章（例: `「容赦ない男たち」の荒廃した日常`、`「〜」の〜`、`『〜』の〜`、`「「〜」〜」`、`果てしない日常` 等）が含まれる場合、あるいは選択肢間に著しい文字種・構造の不揃い（キャラ名の中に孤立した英語曲名や「〜なのか？」等の疑問形曲名・カギ括弧付きタイトル・長文文章が混在している等）がある場合、`TopicData.is_valid` で確実に `False` を返して排除すること。
10. **Bot起動時・バックグラウンドLLMタスクによる過剰生成の抑止（BAN-118）**:
    - `cog_load` における無条件のお題プリフェッチを禁止し、設定 `TIER_GAME_PREFETCH_ON_STARTUP`（デフォルト `False`）でガードすること。
    - `TopicPool._fill_worker` の試行回数上限を最大6回（`min(max(needed * 2, 2), 6)`）に制限し、プール内重複除外引数（`excluded_categories`, `excluded_topics`）を渡してカテゴリ衝突による無駄な再生成ループを恒久防止すること。
11. **カタカナ卑語・文節断片の遮断と主観的表現の正確な判定**:
    - センシティブワード判定（`_SENSITIVE_WORDS_RE`, `_SENSITIVE_THEME_RE`）にカタカナ卑語（チンコ、マンコ、バカマンコ等）を含め、DBテーマ抽出（`_extract_clean_db_theme`）では述語・文節断片（「〜している」「〜いない」「〜存在する」「〜という呼び方」等）を確実に `None` として棄却すること。
    - 客観知識クイズ判定（`_OBJECTIVE_FACT_TOPIC_RE`）において「の種類」を文脈付き（`の種類(?:は|って何|とは|を答え|を教え|が正しい|で正しい)`）で判定し、「お茶の種類で、今一番〜」等の健全な主観好みを誤検知しないこと。

## 🛠️ コーディング規約と検証手順
- **型安全性**: Python 3.11+ 型アノテーションを完全に付与し、`mypy` エラー0件を死守すること。
- **検証コマンド**:
  ```bash
  # 単体テストの実行（サブプロジェクト内およびリポジトリ全体）
  PYTHONPATH=mock_libs:. pytest tier_game/tests/ -q
  PYTHONPATH=mock_libs:. pytest tests/test_tier_game*.py -q
  # 型検査
  PYTHONPATH=mock_libs:. mypy --config-file mypy.ini tier_game
  ```
