# 🤖 Tool Registry ガイドライン (GEMINI.md)

本ディレクトリ（`harness/agent/tool_registry/`）は、AIエージェントの**フェーズ3（Action/ツール選択と実行）**を担当するサブプロジェクトです。

詳細な開発ガイドラインおよび境界条件は、正本である [AGENTS.md](file:///Users/Shadow/Documents/05%20%E9%96%8B%E7%99%BA/discord-ai-bot/harness/agent/tool_registry/AGENTS.md) を参照してください。

> [!IMPORTANT]
> **最優先原則**:
> 1. **境界条件遵守**: 自身のディレクトリ外（`harness/agent/tool_registry/` 外）のファイルを直接編集してはならない。
> 2. **多重防御**: 外部通信（MCP / Web / Weather API）の完全な例外ハンドリングとタイムアウト制御を徹底すること。
> 3. **静的型検査**: Python 3.11+ 型アノテーションと `mypy` エラー0件を維持すること。
> 4. **Webスクレイピングの多重防御**: Wiki等のスクレイピングにおいて目次（TOC）ブロックの事前除去、厳密な見出しタグ走査、メタキーワード・残骸記号の完全サニタイズを徹底すること。
> 5. **日常語・一般疑問詞・PCハードウェア語・パズル文のリサーチ抑制**: 日常カタカナ語やPC/ITハードウェア日常語（パソコン、スマホ、タブレット、モニター、キーボード、メモリ等）および一般語・時事・一般疑問詞・副詞表現（最新、最近、現在、一体、一体何、一体全体、何事、何故、何時等）のストップワード登録と、文字パズル・なぞなぞ・ヒント提示文の `looks_like_puzzle_or_riddle` によるWeb調査・Middle-LLM相談誤発火の多重防御を徹底すること（項目128, 145）。
> 6. **ファクトチェックのブラウザ調査優先化・ノイズ除外**: ファクトチェック・事実確認における `browser_search` 自動昇格、ノイズドメイン（掲示板・知恵袋・成人向け）の品質スコア大幅減点・優先度抑制、および複合キーワード不十分時のクエリリファイン（2nd pass）による裏取り強化を徹底すること。
> 7. **要素分解（Claim Decomposition）・スラング保持・要約抜粋保全**: 検索計画での2〜3個の多角クエリ分解（前提・理由・俗称）、カギ括弧・スラング原文保持、`w.atwiki.jp` 信頼ドメイン追加、要約トークン枠768への拡大、伝聞調のファクトチェック検知強化、および複数クエリ・ファクトチェック時の生抜粋（content_excerpt）保全を徹底すること。
> 8. **Web検索基盤統合（Chrome MCP優先・DDG Lite POST）および歌唱曲名保護・Web装飾除去・歌詞抽出強化**: 統合検索 `search_web_entries_unified` の配備、HTTPフォールバックでの DuckDuckGo Lite (`lite.duckduckgo.com/lite/`) へのPOST検索最優先化、歌唱曲名抽出における引用符内完全保護・7文字以下および「〇〇の歌」誤切断防止、曲名一致判定におけるWeb装飾語句除去・サブストリング照合、および汎用HTML歌詞抽出における全角インデント・短行柔軟判定を徹底すること。
> 9. **URL入力・投稿時の直接閲覧（browser_read_url）ルーティング保証およびDNS検証（SSRF対策）の堅牢化**: `WebSearchToolAdapter` およびディスパッチにおいてクエリ内にURLが含まれる場合の `browser_read_url` ルーティング死守（URL付随コメントによる降格禁止）、およびSSRF検証におけるポート明示・IPv4フォールバック・ブラウザ解決委譲によるDNS一時エラー時のパブリック正規URL遮断防止を徹底すること。
> 10. **対話相手名（User-First）誤検索防止ガードおよび構造化観測ログ**: `WebSearchToolAdapter` において対話相手名（`target_name`）と雑談相槌語（「好きだよね」「脈アリ」等）の誤爆クエリを外部検索前に遮断して案内テキストを返却すること、および `[web-search] Executed query=%r mode=%s fallback_used=%s result_chars=%d` による構造化観測ログ出力を徹底すること。
> 11. **検索クエリへの話者名・例示語混入防止、観察要約への現在日時注入と `num_predict` 下限保証、PDF直リンク除外（項目163, 174）**: `_generate_browser_search_plan` で `補助文脈` の話者名（`雑菌` 等）やプロンプト例示語（`かじゅき` 等）が `user_text` にない限り検索クエリに混入しないようプロンプト改善・ポストフィルタを実施し、`_strip_context_speaker_and_meta_labels` により会話履歴行からの `[HH:MM] 話者名 [>>返信先]:`・`Assistant` ラベル・`詠み手:` 行を事前除去してクエリ汚染を根本遮断すること。また `_summarize_browser_observations` に現在日時注入・`insufficiency_reason` 短文化・`num_predict >= 512` 下限保証を適用して JSON 切断（`OllamaJSONTruncatedError`）を防止し、PDF直リンク（`.pdf` / `/_pdf`）のブラウザ巡回リトライ浪費を抑止すること。
> 12. **MCPブラウザ遷移ログにおけるターゲットURL出力仕様およびWeb本文抜粋のUIノイズクレンジング（BAN-139）**: `MCPChromeHTTPClient.call_tool` で `url` または `query` が含まれる場合に `MCP call_tool started: name=%s target_url=%s` として安全に出力して可観測性を担保し、`_cleanup_browser_text` / `_extract_browser_page` でインプレッション数・エンゲージメント表示やUIボタン文言、アクセシビリティツリー残骸などのUIノイズを汎用的にストリップしてハルシネーションを確実に遮断すること。
> 13. **数値＋単位の複合名詞保護、シミュレーション・影響検証疑問文のWeb調査検知、および調査思考ポリシー補強（項目92, 102）**: `extract_named_term_candidates` で「10万ボルト」「50mA」等の数値＋単位複合名詞の優先抽出と単一単位への分解防止、単一計量単位のストップワード登録、「〜食らったらどうなる」「人体への影響」等のシミュレーション疑問文の `looks_like_simulation_or_impact_verification` による `fact_check_flag` / `browser_search` 検知、およびツールカタログ・ツール定義における数値・設定シミュレーション客観調査ポリシーの徹底。
> 14. **複合動詞ファクトチェック誤爆防止、Bot名・人称代名詞ストップワード保護、およびルールマッチングログ（項目128, 145）**: `_FACT_CHECK_QUESTION_RE` の負の戻り読み（`(?<!付き)(?<!話し)...`）による複合動詞（付き合ってる、話し合ってる等）の `fact_check` 誤爆遮断、`_GENERIC_TERM_STOPWORDS` へのBot一般呼称（アシスタント、AI、ボット、bot等）・人称代名詞（貴様、お前等）・一般名詞（恋人、今恋人、友達、記憶、出来等）の登録、自身の名前・愛称（BOT_ALIASES等）の `get_generic_term_stopwords()` による動的合流、`_PREFERENCE_OR_OPINION_MARKERS` への交際・人間関係表現追加による日常会話保護、および `detect_reply_research_rules` での `[research-rules] Rule matching details` 構造化観測ログ出力の徹底。
> 15. **日常行動・独白文の未知語トリガー抑止および強調接頭辞ストップワード追加（多重防御、項目128, 145）**: `_COMMON_KATAKANA_STOPWORDS` への日常誇張・ゲーム的接頭辞（ウルトラ、ウルトラレア、スーパーレア、ハイパー、メガ、レア等）の登録、および `looks_like_daily_action_or_monologue` による調理・食事・購買・生活行動独白文（「〜で焼く」「〜食べる」「〜買ってきた」「〜に行く」等）の検知と `has_slang_or_unknown_candidate` / `slang_or_unknown_trigger` / `needs_research` 抑制の徹底。
> 16. **会話文脈の共起固有名詞（Context Co-occurrence）Web調査クエリ構築・台詞パロディ検知（項目23, 136, 174）**: `_CHARACTER_DIALOGUE_QUOTE_RE` / `_has_character_dialogue_meme` によるキャラ台詞パロディ検知、`detect_reply_research_rules` での `_strip_context_speaker_and_meta_labels` による本文のみからの `context_named_terms` 抽出、`_GENERIC_TERM_STOPWORDS` への一般疑問語・システムラベル（何年、何年か、配布、交換、Assistant、User、System等）の拡充、疑問を伴わない「まだ〜してない」の `recency_flag` 抑止、キャラ台詞ネタ・未知カタカナ複数語＋文脈固有名詞時の `needs_research` 昇格、および `_build_context_enriched_query` による文脈共起語結合検索クエリ（例: `'エニック シックスオー シュエン ナユタ'`）生成による知ったかぶり・ハルシネーション根本防止の徹底。
> 17. **困りごと・意見募集（相談・解決策模索）の判定と解決策検索クエリ生成（BAN-168）**: `detect_consultation_or_problem_solving_inquiry` による困りごと・疑問・代替手段模索（「してる人いない？」「どうすりゃいい」「途方に暮れてる」等）の検知、単なる体調・感情独白の誤判定遮断、主要語に「代替」「対策」「方法」等を付与した解決策検索クエリ構築、および `looks_like_daily_action_or_monologue` 質問マーカー登録と `consultation_flag` / `hard_trigger` によるWeb調査発火と自己投影ミラーリング防止の徹底。
> 18. **Chrome MCP スクリーンショット取得および Vision モデル（Qwen3-VL-8B）画面解析と即時 VRAM 解放規約（BAN-170, BAN-15）**: `chrome_screenshot` ツールにおける Playwright 高画質スクリーンショット取得、`describe=True` 時の `OLLAMA_VISION_MODEL` による `call_ollama(think=False)` 客観的画面説明、推論終了後の `finally` での `release_ollama_model(target_model, timeout_sec=5.0)` による即時 VRAM 解放、および `describe=False` 時の高速軽量動作の維持。
> 19. **画像検索（search_image）ツール連携と画像コンテキスト検知・リサーチディスパッチ統合（多重防御、BAN-145, BAN-170）**: `search_image` ツールにおける Google Lens / Web検索多重防御、文脈画像URL自動解決、`detect_reply_research_rules` による画像質問検知と `image_search` 自動昇格、`resolve_research_mode` での `browser_read_url` 誤降格防止、`research_dispatch` での統一形式返却、および `register_builtin_tools` での後方互換引数の維持。
> 20. **逆画像検索における偽陽性防止、UIノイズクレンジング、フォールバッククエリサニタイズおよび構造化ロギング（項目114, 139, 1717）**: `_is_lens_error_or_wall` によるエラー画面・ログイン壁検知と Web検索フォールバック誘導、`_format_lens_result` でのUIノイズ除去と視覚的一致行抽出、`_clean_fallback_query` による質問定型句ストリップ・画像URL生投げ遮断、および `[IMAGE_SEARCH]` / `[IMAGE_SEARCH_DISPATCH]` 構造化観測ログの配備。
> 21. **文脈URL参照判定におけるSystem内部メモURL除外および日常質問誤検知防止（多重防御、BAN-28, BAN-55, BAN-136）**: `_looks_like_context_url_reference` における指示代名詞・URL言及なし一般質問の除外、および `detect_reply_research_rules` における `System:` / `(内心のメモ:` 内部システムメモ行の完全除外（消滅URLアクセス・404エラー・目的外Web調査の根本遮断）。
> 22. **動的ブラウザ対象サイト判定への may.2chan.net 追加およびふたばスレッド先頭URL抽出の保証（多重防御）**: `_is_dynamic_browser_site` の対象ホストへの `may.2chan.net` 追加、および `detect_reply_research_rules` の `img_thread_flag` フォールバック時における `img.2chan.net` / `may.2chan.net` 先頭URL走査・抽出の徹底。
> 23. **未知語候補の重複カウント防止、日常口語カタカナ語除外、および文脈固有名詞からの話者名除外（多重防御、項目128, 145, BAN-163）**: `detect_reply_research_rules` において未知語候補は重複を除外してからカウントし（`candidate_term` と `named_terms` の二重計上禁止）、`Character_Dialogue_Or_Context_Entity_Research` の発動条件として「異なる未知カタカナ語が2種類以上」であることを徹底すること。また `_COMMON_KATAKANA_STOPWORDS` に日常口語・感情カタカナ語（ナイショ、ヒミツ、ホント、ウソ、ダメ、ムリ等）を追加し、文脈固有名詞抽出時に話者プレフィックスおよび本文呼びかけ（〇〇さん等）から話者名を除外すること。
> 24. **未知語ストップワード・愛称保護のConfig駆動・動的合算化（多重防御、項目174, BAN-128, BAN-145）**: `_GENERIC_TERM_STOPWORDS` から特定キャラクター固有語（コイト、福丸小糸、シャンクス等）の固定ハードコードを削除し汎用ストップワードのみを残すこと、`get_generic_term_stopwords() -> set[str]` による `lib.config_utils.cfg`（`OLLAMA_BOT_DISPLAY_NAME`, `BOT_FIRST_PERSON`, `BOT_ALIASES`）の動的合流、および全ストップワード照合箇所での一貫した動的合算利用の徹底。
